# Change Vizier safely

Read `vizier/AGENTS.md`, the applicable Semantics repository, and the exact
affected architecture, CLI, persistence, installation, and Chancery contracts
before editing. Use the current installed Nucleus requester contract and
operator manual when the requester, durable state, compatibility, or lifecycle
boundary changes.

Keep changes inside Vizier authority. Meaning-bearing documents remain exact
opaque Markdown. Structure only identity, digest, lineage, packet edges, roles,
jobs, workspaces, candidates, dispositions, gates, and lifecycle. An
implementor or integrator cannot accept its own edits; remediation gets a
targeted recheck, not another broad audit.

Preserve the central proof rule: a model response or terminal Nucleus job is
not Vizier success. Planning, implementation, review, integration, and gates
advance only through validated durable Vizier evidence bound to exact inputs
and Git candidates.

Run the product gate and Cell root gate. Add proportional tests for every
changed document, ledger, requester, Git, review, recovery, privacy, or
installation seam. Use synthetic data only.

`release.sh` commits, tags, and pushes. The macOS deployer changes installed
selectors. Neither action is authorized by ordinary development work, and a
Vizier change never grants authority to modify Nucleus, Git, Semantics,
Pratica, or another product.
