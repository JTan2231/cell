# Cast

Cast discovers employer candidates, collects public job postings, and retains
the evidence needed for downstream job selection. It owns company and job
identities, extracted records, source metadata, collection outcomes, local
request budgets, and the consistent read handoff.

Downstream products own personal selection, application packets, CRM cases,
application submission, and email delivery. External providers own their
responses, availability, rate limits, and billing. Cast uses Rust and bounded
HTTP requests. It runs no model, Nucleus job, computer-use tool, or downstream
application workflow.

Read the installed overview with `chancery product cast`. Read one feature with
`chancery show ID`. Read an operation and its required feature contracts with
`chancery resolve ID`. These commands read documentation. They do not establish
provider readiness, authorize work, or execute the documented interfaces.

## Features

| ID | Read this to understand |
| --- | --- |
| `cast.discovery.collect` | Due-work discovery, careers refresh, exact job-URL collection, source ownership checks, request admission, and collection outcomes. |
| `cast.discovery.explore` | Company and job meaning, availability and freshness, stable identities, read projections, and consistent exports for consumers. |
| `cast.state` | Private state selection, configuration, source controls, budget defaults, ownership reconciliation, and state recovery. |
| `cast.installation` | Matching program and documentation releases, selectors, wrapper credentials, deployment setup, and program recovery. |

## Operation

Use `cast.install.operate` to install or recover programs, initialize or
configure discovery state, diagnose readiness, control sources, or reconcile
older ownership records. The procedure keeps prerequisites, consequential
effects, stop conditions, and verification in place. Its required feature
contracts supply the detailed explanations.

## How the features work together

Initialization selects a private state directory. Configuration supplies query
families, source policy, and local caps. A collection invocation selects due
work or one exact posting, reserves request cost, and retains observations and
explicit collection outcomes. A partial run can leave successful observations
durable while other steps fail or remain deferred.

Read interfaces return stored evidence without collecting. A consistent export
includes stable identities, revisions, capture time, source health, and query
coverage. Consumers compare records and decide which jobs to select. Retained
job counts and source observation times do not establish complete or current
coverage of all external postings.

Program installation and discovery state have separate lifecycles. Program
recovery selects a verified retained release; it does not restore state or
consumed allowance. Installation creates no collection schedule. Another
collection requires another invocation.

Feature pages own the behavior described here. Related references provide
navigation; required dependencies define compatible documentation closure.
Those dependencies do not transfer authority or create runtime calls.
