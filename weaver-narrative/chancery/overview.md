# Weaver

Weaver turns one free-form direction into a private Markdown narrative. Its
author reads Krisis decision documents accepted into Annals and uses the
direction to choose audience, form, voice, length, selection, and emphasis.
Weaver owns the saved document and its exact authoring recovery state. Annals
owns source text; Nucleus owns execution and authentication.

Read one feature with `chancery show ID`. Read a procedure and its required
contracts with `chancery resolve ID`. Read this installed overview with
`chancery product weaver`. These reads do not establish live readiness or
authorize an operation.

## Operations

Use `weaver.install.operate` to install, configure, inspect or recover
Weaver through the maintained Cell coordinator and current-user commands.
Use `weaver.develop.change` to change prompts, software, or contracts while
preserving the supported workflow and publishing matched documentation.

## How the features work together

Configuration selects an explicit Annals decisions library. Prompt preparation
resolves the complete Weaver selection from Bazaar. Weaver saves an exact
Nucleus request before admission and retains its document/job identity.
Nucleus admits one authoring attempt. The agent reads accepted documents on
demand and submits Markdown through Weaver's tool.

Saved Markdown is Weaver's result. Runtime completion without a document is an
error; a later runtime failure does not erase saved prose. Resume reuses the
exact request and job, and current reading configuration. A revision creates
another independent document. A batch collects each assignment's outcome.

Maintenance blocks new authoring while exact existing work can settle.
Deployment keeps program and provider selection together. Weaver has no
background worker, service, or schedule. It does not publish narratives, send
email, mutate sources, certify interpretation, or retry terminal jobs.

Required dependencies declare compatible contract reading. Related references
provide navigation. Neither transfers product authority or creates a runtime
dependency on Chancery. Unspecified limits and external reliance gaps remain
visible in `resolve`; installed documentation does not prove dependency readiness.
