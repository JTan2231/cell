# Agent instructions

Semantics-Project: conatus

- Keep changes simple. Conatus preserves wants and organizes accepted decision
  documents through its dedicated Annals library.
- Until the `conatus` Semantics project is registered, use the `cell` repository
  for terminology. After registration, read `semantics.repository.explore`
  through Chancery and query `conatus` before analysis or changes. Do not edit
  Semantics state directly.
- Preserve want wording exactly. Do not infer qualifications, priorities,
  deadlines, lifecycle fields, or additional wants.
- Conatus owns source intake, feed cursors, outgoing documents, receipts, and
  product views. Annals owns the retained works, instructions, concept graph,
  evidence, revisions, model integration, and domain recovery.
- Use supported Annals interfaces. Do not edit its database or spool directly.
  Enqueue new sources before retention; an inbox duplicate does not request
  another examination.
- Keep captured, queued, retained, and interpreted outcomes distinct. Label
  counts, timestamps, and failures by the operation or records they describe.
- Read `nucleus manual` before changing shared boundaries. Update product
  documentation and Chancery source contracts with the implementation, and
  shared operational facts in `nucleus/docs/operator-manual.md` when affected.
- Installation, initialization, schedule activation, and model execution are
  separate effects. Source presence does not establish deployment or readiness.
- Every code change must leave the default `./ci.sh` green. A user-requested
  stop before testing takes precedence; report validation as not run.
