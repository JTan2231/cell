# Conatus

Conatus preserves wants in their source wording. It consumes new accepted
decision documents from an explicitly selected Annals decisions library and
asks its dedicated general Annals library to organize them by the wants they
appear to serve. It can send a deterministic personal email of active wants
and existing direct decision quotations.

Conatus owns intake, the feed cursor, frozen outgoing documents, handoff
receipts, want archive state, processing gates, selected library instructions,
product views, and frozen email occurrences. Annals owns retained works,
instruction identities, evidence, concepts, revisions, interpretation and
domain recovery. Associations express interpretation. They do not establish
progress, enactment, completion, or current force.

Read `chancery show ID` for one feature or procedure. Read
`chancery resolve ID` for its required contract reading and compatibility gaps.
Read `chancery product conatus` for this overview and the inventory. Installed
publication does not establish readiness or grant authority to perform work.

## Features

| ID | Read this to understand |
| --- | --- |
| `conatus.want.capture` | Exact want wording, opaque provenance, local capture and frozen source identity. |
| `conatus.want.lifecycle` | Explicit archive and unarchive, local current state and active selection. |
| `conatus.library.explore` | Intake records, associations, evidence, bounded graph views and processing observations. |
| `conatus.processing` | Initialization, feed coverage, unchanged document handoff, instructions, Annals interpretation and recovery. |
| `conatus.digest.email` | Complete active-want content, direct quotations, frozen occurrences, disclosure and uncertain submission. |
| `conatus.service` | Matched program and documentation releases, maintenance, update and email schedules, and failure halts. |

## Operations

Use `conatus.update.operate` to initialize, update, recover or change instructions,
install a release, prepare and activate schedules, or operate maintenance.
The procedure keeps its prerequisites, consequential effects, stop conditions
and verification. Required feature contracts supply the complete explanations.
The existing operation ID and contract version remain supported.

## How the features work together

Capture commits a want locally. An update consumes the new accepted-document
feed prefix, queues frozen sources, and dispatches the dedicated Annals inbox.
Captured, queued, retained and interpreted are separate outcomes. The feed
cursor describes intake coverage. It does not describe interpretation coverage.

Want archive state affects default lists and newly rendered email. It does not
change Annals sources, processing or graph state. Email reads current intake
and existing evidence; it does not update the library or start a model.

Clockwork supplies two independent activations. Installation, initialization
and schedule activation are separate effects. Product pause, Annals pause,
Clockwork incidents and email submission uncertainty each have their own
recovery. Release recovery does not revert domain state.

Required dependencies mean documentation compatibility. They do not transfer
authority or create runtime calls. Related Chancery references provide navigation
without adding a dependency. The owning product release includes this overview,
the indexed entries and their complete pages in its immutable provider bundle.
